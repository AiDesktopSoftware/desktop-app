# 模块边界规则（三人协作）

## 目录归属

| 目录 | 负责人 | 说明 |
|---|---|---|
| `src/renderer/src/views/chat/` | 龙 | 对话模式 |
| `src/renderer/src/views/work/` | 赵 | 工作模式 |
| `src/renderer/src/views/info/` | 胡 | 信息模式 |
| `src/renderer/src/App.vue`、`assets/main.css`、`src/main/`、`src/preload/` | 公共 | 外壳、主题、进程层 |

## 铁律

1. **只改自己负责的目录**。别人负责的模块目录只读，不得添加示例内容、mock 数据、样式或占位业务。
2. 自己的模块里写什么由负责人决定；其他人不要"顺手美化"或"帮忙补齐"。
3. 需要跨模块协作时，通过约定好的 API / 数据格式，不要直接引用对方模块内部实现。
4. 修改公共文件（App.vue、main.css、主进程）前，先确认不会影响另外两个模块；必要时走 `feat/` 分支 + PR。
5. 每个人负责的模块，其样式写在自己 `.vue` 的 `<style scoped>` 里，公共样式只放外壳级变量与布局。
6. **分支隔离**：赵的模块改动只在 `feat/zhao-work` 分支，公共外壳改动才进 `main`（详见 git-workflow.md）。
7. **本地备份不可省**：大改前、跑通后执行 `npm run backup`，已跑通内容不得被删除或覆盖。
