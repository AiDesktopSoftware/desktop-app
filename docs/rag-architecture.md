# 双通道 RAG 与可编排工作流方案

> 结论：不做内网穿透，不买服务器。公共库走阿里云百炼托管知识库，私有库在本机建。
> 上层不是固定流水线，而是 **L2 级可编排工作流**：用户从模板复制，增删步骤、调顺序、改参数。

---

## 一、方案要点

| 项 | 决策 |
|---|---|
| 工作流自由度 | **L2**：步骤增删 / 排序 / 启用开关 / 参数调整 |
| 用户起点 | **从模板复制改**，不从空白搭 |
| 公共 RAG | 阿里云百炼托管知识库，只调**检索** API |
| 本地 RAG | 本机 Python + FastAPI，仅监听 `127.0.0.1` |
| 嵌入模型 | 硅基流动 `BAAI/bge-m3`（OpenAI 兼容，有免费额度） |
| 向量存储 | SQLite + 向量扩展（单文件） |
| 生成模型 | DeepSeek（现在）→ 龙的模型服务（后续，OpenAI 兼容） |
| 执行语义 | **顺序执行**，不做并行、不做 DAG |
| 统一原则 | 所有节点只处理「片段 / 文本」，生成永远在本地做 |

### 为什么是 L2 而不是画布

| 档次 | 用户可改 | 工作量 | 判断 |
|---|---|---|---|
| L1 配置 | 选库、选模型、topK | 小 | 太浅，体现不出「DIY」 |
| **L2 编排** | 步骤增删、排序、开关、参数 | 中 | **选它**：演示效果够、可控 |
| L3 扩展 | 用户写工具注册成节点 | 大 | 只留 HTTP 占位，不实现 |
| L4 画布 | 拖拽连线、分支、并行 | 很大 | 不做，会把时间从 RAG 效果上挤走 |

## 二、架构

```
┌────────────────────────── Electron 桌面端 ──────────────────────────┐
│ 渲染层（Vue）                                                        │
│   工作模式：选工作流 → 看步骤 → 运行时看每步状态与证据                  │
│        │ IPC                                                         │
│   主进程（TS）                                                       │
│     ├ 工作流执行器（按步骤顺序跑，维护上下文）                          │
│     ├ Agent 工具循环（对话模式沿用，不替换）                           │
│     └ 节点注册表（能力目录）                                           │
│            │                                                         │
│   ┌────────┼──────────┬──────────────┬───────────────┐               │
│   ▼        ▼          ▼              ▼               ▼               │
│ 本地RAG  百炼检索   联网搜索      模型调用        文件导出            │
│ 127.0.0.1  HTTPS      HTTPS    DeepSeek/龙       本机                │
│   │                                                                  │
│ SQLite 向量库 + 原始文件                                              │
└──────────────────────────────────────────────────────────────────────┘
```

要点：

1. 本地 RAG 是 `127.0.0.1` 回环服务，不需要穿透，但对上层仍是 HTTP 接口，和云端节点调用形态一致。
2. 云端只调「检索」不调「问答」，因此龙的位置没有被挤掉：片段照样回流本地生成。
3. 工作流是新增能力，**不替换**现有的对话 / Agent 模式。

## 三、工作流模型（本方案核心）

### 3.1 工作流结构

| 字段 | 说明 |
|---|---|
| `id` / `name` / `description` | 标识与展示信息 |
| `builtin` | 内置模板为只读；用户复制后生成自己的副本 |
| `version` | 结构版本，便于以后升级不破坏旧流程 |
| `steps[]` | 步骤数组，**数组顺序即执行顺序** |

单个步骤字段：

| 字段 | 说明 |
|---|---|
| `id` | 步骤唯一标识 |
| `nodeType` | 能力类型，见 3.3 |
| `name` | 用户可改的显示名 |
| `enabled` | 开关。关掉的步骤跳过——**用它代替条件分支** |
| `params` | 该节点的参数，按节点定义校验 |
| `onError` | `stop`（默认）/ `continue` / `retry` |

**不做的事**：不做任意跳转、不做表达式、不做并行。用户想表达「这一步要不要跑」就用开关，简单且不会搭出死循环。

### 3.2 执行上下文

步骤之间通过一份共享上下文传递，节点只读写自己声明的那部分：

| 上下文槽位 | 内容 |
|---|---|
| `query` | 用户本次的原始问题 |
| `docs[]` | 导入或采集到的文档 |
| `chunks[]` | 检索或合并得到的片段 |
| `text` | 当前生成的文本 |
| `artifacts[]` | 导出的文件、报告 |

每个节点声明 `consumes`（读哪些槽）与 `produces`（写哪些槽）。执行器在**运行前**校验：每个节点需要的槽，必须在它之前的步骤里已经被产出，否则直接拒绝运行并指出是哪一步缺输入。这样即使用户把步骤顺序调乱，也能在跑之前就发现，而不是跑到一半报错。

### 3.3 节点清单（能力目录）

| 节点类型 | 显示名 | 归属 | 输入 | 输出 | 阶段 |
|---|---|---|---|---|---|
| `source.file` | 导入本地文档 | 赵 | 路径 | `docs` | P1 |
| `source.web` | 网页采集 | 胡 | URL / 关键词 | `docs` | P2 |
| `rag.local` | 本地库检索 | 赵 | `query` | `chunks` | P1 |
| `rag.cloud` | 云端库检索 | 赵 | `query` | `chunks` | P2 |
| `rag.merge` | 片段合并去重 | 赵 | `chunks` × N | `chunks` | P2 |
| `tool.search` | 联网搜索 | 公共（已实现） | `query` | `docs` | P2 |
| `tool.fetch` | 读取网页 | 公共（已实现） | URL | `docs` | P2 |
| `llm.analyze` | 模型分析生成 | 龙 / DeepSeek | `chunks` / `docs` | `text` | P1 |
| `output.report` | 导出报告 | 赵 | `text` + `chunks` | `artifacts` | P3 |
| `ext.http` | 自定义接口 | 预留 | 任意 | 任意 | 不实现 |

现有 `tools.ts` 的 6 个工具可以直接映射为节点，不需要重写——这是这套设计最省力的地方。

### 3.4 校验、失败与可观测

**运行前校验**：至少一个终端节点（生成或导出）、输入槽齐全、必填参数完整、依赖的外部能力已配置。未配置的能力（如百炼 Key 缺失）标记为不可用，运行时禁用该步并给出提示，而不是崩掉整条流程。

**失败策略**：默认停在该步，保留已完成步骤的中间结果；网络类节点可退避重试一次；用户可把单步设为 `continue`。

**可观测**：每步记录状态、耗时、入参摘要、输出摘要。复用现有的「执行轨迹」面板，不新造一套。

### 3.5 存储

工作流存本地文件（用户数据目录下每个流程一个文件），复用现有 `store.ts` 的原子写法。内置模板随应用打包、只读；用户「复制」后生成可编辑副本。不引入数据库。

### 3.6 内置模板

| 模板 | 步骤 | 用途 |
|---|---|---|
| 快速问答 | 本地检索 → 生成 | 单库、最快出结果 |
| 双库交叉验证 | 本地检索 + 云端检索 → 合并 → 生成 | 展示双通道价值 |
| 深度研究 | 联网搜索 → 读网页 → 本地检索 → 合并 → 生成 → 导出 | 完整研究流程 |

用户要 DIY，实际是从这三条里挑一条、改一两步。这既降低使用门槛，也降低实现复杂度。

## 四、双通道 RAG（作为节点实现）

| 环节 | 选型 | 理由 |
|---|---|---|
| 公共知识库 | 阿里云百炼 | 国内直连、有免费额度、检索 API 独立可调 |
| 嵌入 | 硅基流动 `BAAI/bge-m3` | 补齐 DeepSeek 无 embedding 接口的缺口，OpenAI 兼容 |
| 向量库 | SQLite + 向量扩展 | 单文件、零服务，符合本地存储偏好 |
| 本地服务 | Python + FastAPI | PDF/Word 解析生态在 Python；也符合课程对 Python 后端的要求 |
| 文档解析 | PyMuPDF / python-docx / BeautifulSoup | 覆盖网页、PDF、Word 三类来源 |

> 本地 RAG 服务由主进程启动时拉起，端口随机后回写配置，退出时一并结束。
> 这是本方案唯一增加的运行复杂度，换来的是不重写 PDF 解析与中文切分。

**嵌入只在建库时做一次，检索本身极轻**——这是「不买服务器」能成立的根本原因。

## 五、三人分工：从流水线到节点

| 人 | 固定流水线里 | 节点化之后 |
|---|---|---|
| 胡 | 上游，必须先给数据 | 采集节点，用户可选可不选 |
| 赵 | 中间，必经 | 检索 / 合并 / 导出节点，自由组合 |
| 龙 | 下游，最后调用 | 模型节点，与 DeepSeek 并存，二选一 |

好处：三个人的能力通过节点契约被组装成任意流程，答辩可讲「模块化 + 可编排」。
风险：**节点契约一旦漂移，三个人的东西拼不起来**。所以契约要在 P0 冻结，之后改走 PR。

## 六、接口契约

### 6.1 胡 → 赵（离线文件，不走网络）

JSONL，一行一篇，必填：`docId`、`title`、`content`、`sourceUrl`、`sourceType`、`collectedAt`、`rawPath`；可选：`publishedAt`、`tags`。

### 6.2 节点契约（三人共守）

每个节点对外只暴露：类型标识、显示名、输入槽、输出槽、参数定义（键 / 类型 / 是否必填 / 默认值）。**不暴露内部实现**，调用方也不许依赖节点内部细节。

### 6.3 赵 → 龙

龙的服务按 OpenAI 兼容暴露 `/v1/chat/completions`，赵侧只改 `baseUrl`，工作流链路不感知模型来源。

## 七、分阶段

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0** | 结构定义 + 3 个模板 + 编排界面 + 执行器（节点全 mock）+ 持久化 | 复制模板 → 删一步、调顺序、改参数 → 运行 → 每步状态与耗时可看 → 重启后仍在 |
| P1 | 本地 RAG 三节点真实化：导入、检索、生成 | 导入一份 PDF → 提问 → 命中片段 → 回答带引用 |
| P2 | 云端检索 + 合并 + 联网节点 | 切到双库模板，两路结果合并去重，来源标注清楚 |
| P3 | 导出节点 + 证据链加固 | 报告可导出，证据可回溯到原文 |
| P4 | 模型节点切到龙的服务 | 只改配置即可切换，流程不变 |

P0–P3 不依赖队友；胡的数据到了按 JSONL 灌入，龙的服务好了加一个节点配置。

---

## 八、明确不做

- 内网穿透（frp、各类隧道）、自建或租用云服务器
- 拖拽画布、并行执行、任意跳转与条件表达式
- 用户自定义代码节点（只留 HTTP 占位，不实现）
- 多用户账号与权限体系
- 「云端库端到端直接答」作为主链路

## 九、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 自由度过高，用户搭出跑不通的流程 | 体验差、看起来像半成品 | 运行前校验 + 模板兜底 + 报错定位到步骤 |
| 节点契约反复改 | 三人拼不起来 | P0 冻结 v1，变更走 PR |
| 编排 UI 挤占 RAG 效果的时间 | 核心卖点变弱 | P0 只做壳，P1 必须交出真实检索 |
| 百炼需实名开通、要 workspaceId | P2 卡住 | P0/P1 不依赖它，提前开通 |
| 嵌入免费额度有速率限制 | 批量建库失败 | 分批 + 退避重试；建库是一次性动作 |
| 三人共享一套 Key | 泄露与额度被刷 | Key 只存主进程配置（已 gitignore），界面只显示后四位 |
| 演示现场断网 | 云端节点不可用 | 本地库兜底；演示文档预先灌入本地库 |
| Python 服务随应用启停 | 打包后进程管理复杂 | 端口随机 + 健康检查 + 退出清理；先开发态跑通再打包 |
| 本地库与文档不同步 | 检索到已删内容 | 入库记录文件指纹，删除时级联清理片段 |
